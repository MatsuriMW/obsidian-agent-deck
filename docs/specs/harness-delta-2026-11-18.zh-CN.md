## 1. 运行时记忆查询：从"只能吃注入"到"能主动查"

**以前**：派发时按任务文本做一次词面重合（≥2 个词）挑选，最多 5 条 / 1200 字塞进 prompt。问错了只能重派一次。33 条记忆里没被挑中的，Agent 根本不知道存在。

**现在**：`scripts/memory-query.mjs`，三个动词，只读：

```bash
node "<库>/.obsidian/plugins/agent-deck/scripts/memory-query.mjs" search "拒答门槛" [--k 5]
node "…/memory-query.mjs" read <记忆文件名>
node "…/memory-query.mjs" recent [10]

# 时间窗 / 只想要区间内的那条
node "…/memory-query.mjs" search "拒答门槛" --since 2026-11-01 --until 2026-11-18
```

口径（有意为之，不是随便定的）：

- 每条命中带 `命中：词1、词2` 当 **why**，**不打印分数**——分数难验证，算错了会安静地丢上下文。
- 门槛是"命中查询词的一半"：中文二元组太容易误配（"完全不存在的词"会撞上"存在""在的"），不够一半宁可返回空。
- `search` / `recent` 只看 `state=有效`，与自动注入同一个池子；`read` 能打开任意一条。
- **时间**：`--since / --until`（`YYYY-MM-DD`），没写日期的条目不参与过滤，结果尾部会说排除了几条。
- **变更可见**：`supersedes` 双向显示——新写「取代：[[旧]]（日期）」，旧的那条反向写「已被取代：[[新]]」；偏好变了要能同时看见新旧与日期。
- **一跳图检索**：同引同一篇日记的记忆标「同源（同引 日记/…）」，`sources` 指向的原文给**能打开的绝对路径**；打不开（改名/删除）就不编路径。
- `read` 只接受记忆目录内的文件名，挡 `../`；不解析 `记忆.base`。
- 库根从脚本位置向上找 `.obsidian`，记忆目录跟随 `settings.dream.dir`，`--vault` 可覆盖；输出超 6000 字会明说省略几条。

**接线**：脚本随 `npm run install:plugin` 装进插件目录；`Delegator.memoryToolHint` 在脚本与记忆目录都在时，往派发/草稿 prompt 顶部加一行用法。派发一次，Agent 就照着跑（真机验证：`search "拒答门槛"` 命中 2 条，退出码 0，抄回 `[[日记/2026_11_06#^mem-730d323d]]`）。

**因此能做到**：Agent 判断"背景不够"时自己查库、自己溯源到日记块，而不是等人重新派发；用法可随时用 CLI 手跑核对。

## 2. 富化边界：只把真正会被当素材的东西列进去

`src/delegation.js` 的 `enrichPrompt` 现在：

- 代码块、行内代码里的 `[[…]]` **不算引用**（之前会把示例代码里的链接当素材）；
- 任务块自己挂的 `📝`/`📄`（`Agent Deck/派发/` 下的载荷、草稿）**不算素材**（之前草稿生成过一次后，下次派发会把载荷文件列成"被引用笔记"）；
- 任务块自身、解析不到的目标、非 md 目标（图片、canvas）都不列；
- 同名笔记按 `metadataCache` 解析结果列一次，不重复；
- 草稿里已经带过的行（用法行、引用笔记清单、技能行）不再重复前置。

## 3. 载荷快照：文件里有的，才是真的

**以前的裂缝**：prompt 写着"本次任务的完整载荷… 两者冲突时以文件为准"，但派发是**先落盘、后富化**，所以文件里缺引用笔记 / 技能路径 / 工具用法三样。Agent 真按"以文件为准"读，就丢了上下文；这份载荷还是归档快照，事后看也是残的。

**现在**：`Delegator.payloadSnapshot()` —— 没有草稿时**先富化再落盘**；有草稿时仍按草稿原文再富化一次（去重兜底）。真机无草稿派发后，载荷文件第 8 行就是用法行，prompt 里同一行只出现一次。

**因此能做到**：派发出去的那份 Markdown 自洽——人离线改草稿、或事后翻归档，看到的和 Agent 拿到的是一份东西。

## 4. 子代理可见性：谁是谁开出来的

**以前**：`readers.js` 早就解析出 `parentSid` / `parentTitle`，但面板里只是"平铺 + 一段文字说从哪开出"，而且任何带 `parentSid` 的卡片都无条件缩进 18px——父不在当前列表时，等于凭空捏造层级。

**现在**：`src/session-tree.js` 先序排父后子，层级写进 `--ad-tree-depth` 逐层缩进；三种分组（flat / 按 agent / 按项目）都按树序渲染。父不在列表、自环、成环都铺平到顶层，**一张卡都不丢**。缩进只在"父真在同一列表里"时发生。

**顺手纠正一个口径**：`analytics.js` / `dream.js` 并**没有**也不需要"排除子代理"的过滤——Claude 的 subagent 日志在 `readers.js` 就被折进父会话 sid（`fc.parentSid` + `fc.sub`），token 早就算在父头上了。

## 5. 管家中途看护：卡住能被看见，而不是等汇总

**以前**：管家只在全员完成后写一次总结。一个会话卡 40 分钟，要到收尾才暴露。

**现在**：`settings.stewardWatch`（默认**关**，设置页「管家汇总」卡里可开）。开着时每 5 分钟跑一次 `stewardWatchTick`：

- 判定：**运行中 + 15 分钟没有输出**才算卡住（`src/steward-watch.js`）。
- 出错与待授权**不**在这里重复提醒：前者已由 `onWorkbenchJobSettled` 写回 `ERRORED`，后者已由 `attention.js` + `checkAttention` 弹通知；但分类仍复用 `attentionReason`（出错里"首轮需要审批或交互"归到授权那条路）。
- 去重：条件键 `waveId:jobId:kind` 记在 `wave.watchSeen`，同一条件只提醒一次；条件消失后清键，复发可再报。
- 写回：子卡下一行 `- ⚠️ 管家：<标题> 已经 N 分钟没有输出（最后动静：…）`，**不碰任务关键字、不重发**。

**因此能做到**：等的人在 15 分钟量级知道"这条卡住了"，看板上留下痕迹；不会因为没人通知而白等到晚上。

## 6. 删除守卫：不该写的时候不写

`updateNote` 现在先查 `vault.getAbstractFileByPath(path)`：明确为 `null`（笔记已被删/改名）就直接返回，不往残留编辑器里写。

起因是真实事故：验完删掉被派发的临时笔记，插件的回写落到了另一篇正开着的笔记上，**覆盖掉了一张交接卡**（已恢复）。守卫把"不该写"这条路堵住了；确切触发机制没有 100% 复现，所以这条按"防御性修复 + 单测"对待。

## 10. 回复协议：❓ / ✍️ / 💬 三行就是一轮问答（已实现）

派发出去的工作经常要"回话"。以前有四条半成品通道（`💬` 结论、`❓` 问句、续聊、权限通知），各管一段、互不相认。现在收敛成笔记里的一条双向记录：

```
- DOING 🤖 发布插件 ^ad-release
  - ❓ 第2轮：版本号用 1.9.6 还是 2.0.0？   <!-- ad-turn:…:2 -->
  - ✍️ 答：用 1.9.6                        ← 你手写，或按钮写进来（同一行）
  - 💬 第3轮：按 1.9.6 发布，已完成
```

- **状态不另造关键字**：`❓` 未答 = 等你，写了 `✍️` = 已答，之后出现 `💬` = 已跑完。刻意不自动改任务关键字，避免和 sync 的关键字写入打架。
- **四条规矩**：① 回复优先落文本（按钮只是往那行写字的快捷方式）；② 回答有固定位置（prompt 里单独一段「问 / 答」，只带最近 3 轮）；③ 幂等（同句不重复、已有 `✍️` 原地改、多块笔记按块号定位）；④ 不做自由聊天——上下文所有权留在笔记。
- **入口**：`Ctrl+Alt+R`（弹窗，含"从问句抽出的选项 chips"与「回答并继续」）/ 命令「在提问下补一行 ✍️ 答」/ 任务操作菜单里的「✍️ 回复这一问…」。
- **续聊**：「回答并继续」把回答作为下一轮追问发给**原来那个会话**（`Delegator.continueSession`），不新开；失败会提示且回答已落笔记。
- **还没做**：从 attention 通知直接跳到回复弹窗（通知仍打开会话，回复入口在任务菜单/命令）；回复的跨设备同步（手机上写同一行即可，无额外通道）。
