# Agent Deck 1.9.4 修复与审查记录

日期：2026-11-15。

## 最终范围

委派只保留桌面端、后台执行和终端交互。插件内对话窗口只读，可查看和归档。

用户最初要求后台回传不压缩，随后确认改为：日记只写约 150～300 字的进展／结论并附原文链接，完整回复自动另存。实现采用最多约 240 字的本地摘录，不额外调用模型；完整用户消息与回复保存到 `Agent Deck/Conversations/`。工具结果、内部推理与附件不在正文归档范围内。

## 问题与根因

- 多个任务同时完成时，绑定链接虽已排队，结果和归档回链仍可能分别读取旧副本并覆盖。仅将最终写入改成异步不能解决这一问题。
- 自动整理在等待模型时持有旧日志副本；用户新输入会导致本轮失败或延后。
- Claude 无头执行只保留最后一块 stdout 的短预览，不能用来归档完整输出。Qoder 在进程 exit 时收尾并 trim，可能丢失尚未排空的输出及首尾空白。
- WorkBuddy 已有终端入口，但 CLI 会话判断遗漏 WorkBuddy，导致自动绑定可能失效。CLI 会话无法导入桌面，因此必须继续回终端。
- Qoder 显式后台任务未登录时会切到桌面，违反本次工作位置选择。
- 已保存轮次的循环条件反复扫描整个任务块，长日志的这一段耗时随记录数平方增长。隐藏编号的光标检查也会重复解析整篇日记。

## 最终修改

- 按笔记路径共享队列，覆盖绑定、结果、归档链接和自动整理的应用阶段。模型调用在队列外执行，返回后重新读取日志。不同笔记不互相阻塞。
- 打开的源代码／实时预览编辑器以当前内容生成局部事务；输入法正在组字时等待提交。阅读视图和关闭的笔记在 `Vault.process()` 内合并最新内容。异步旧副本有变化时拒绝覆盖。
- 归档目录创建也按路径排队；归档使用最新内容并验证生成区哈希，保留区外备注，生成区被手改时拒绝替换。
- 完整捕获 Claude stdout，使用 UTF-8 流解码并等待 close。Qoder 保留原始输出及尾部换行；Codex 保留同轮多段助手消息并按消息 ID 去重。
- 日记保留短摘录与原文链接；后台会话跳过二次润色及累计合并。正文只在归档中完整保存。
- 复用任务行动态条；后台任务不使用步骤数伪装百分比，完成和失败保留耗时。
- 修复 WorkBuddy CLI 绑定与恢复路径；Qoder 后台未登录时报告失败，不打开桌面。
- 缓存已保存记录的块尾位置；隐藏编号光标保护只检查受影响行。
- 中英文 README、交接文档与 Linear 接入原则同步，移除插件内续聊要求。

## 尝试与修正

最初按“不压缩”实现日记完整正文，在用户确认新方案后改为短摘录与完整归档。新增测试先复现原有截断和并发覆盖，再验证新行为。全量回归暴露两处测试问题：归档替身未按路径读取文件，以及 Qoder 测试固定等待 120 ms 的时序竞争；分别补齐替身契约并改为等待真实终态。没有为这些测试问题修改对应产品行为。

## 性能

同机、2,000 条已保存记录、新增一轮、各 9 次同步：中位耗时 141.92 ms → 2.75 ms；观测到的 p95 149.25 ms → 4.88 ms。这是日志同步函数的基准，不能代表整个插件启动或模型响应耗时。

## 依据与边界

[Obsidian Vault 官方文档](https://docs.obsidian.md/Plugins/Vault)建议基于最新内容使用原子 `process()`；异步处理后检查内容是否变化。

[CodeMirror 协作编辑](https://codemirror.net/examples/collab/)使用版本历史与操作变换；[Yjs](https://docs.yjs.dev/)以共享 CRDT 文档合并更新。二者都要求参与者接入同一协作机制。当前插件集中接收本机 Agent 日志，不引入分布式编辑基础设施。

保护范围是经 Agent Deck 写入的记录及当前编辑器。外部脚本直接覆盖 Markdown、多设备同时编辑同一文件，不受本机队列控制。Agent Deck 不自动为各 Agent 单独提交 Git；提交保存的是当时的整篇日记，来源可通过会话标记和原文链接追溯。

经验：并发保护必须覆盖读取、合并和写入的全过程；完整原始输出与日常回顾内容应分别保存，缩短展示不能丢失原文。
