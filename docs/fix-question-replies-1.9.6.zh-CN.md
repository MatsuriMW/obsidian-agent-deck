# Fix Report：确认消息标签进入日志及用户标题被改写

## 表现与根因

确认选项回传以 `send_user_message_question_reply` 包装 JSON。旧清洗器未识别该格式，简略日志直接截取提问开头，导致标签出现在“任务”字段；旧解析缓存会保留同样的提问。

已有标题虽然使用了当前笔记中的文字，格式化时仍会剥离时间样式前缀并压缩空格。自动记录还会因历史 `created` 标记恢复用户已经去掉的自动标题格式。

## 复现与尝试

先运行 `node --test test/user-question-replies.test.mjs`，原实现的三项确认消息测试全部失败；标题测试也复现了时间前缀和双空格丢失。

保留确认答案并转成可读文字，避免直接忽略整个回传而丢失用户选择。实际日志测试补齐 token 事件后，验证完整的 Codex 读取路径。

不批量重写历史：异常记录仅修正带当前会话来源标记、没有独立块号和子内容的任务字段。保留已有结论、手写内容及用户复用的记录。

## 最终改动

- 读取器与写入器共用提示词清洗逻辑，确认消息提取答案，空回传不计提问。写入器也能处理旧缓存中的回传文字。
- 解析缓存版本从 5 升到 6，升级后重新读取日志。
- 已有标题按原文保留；状态、时间和后续记录照常更新。新生成标题仍使用原有规范。

## 检查依据

已核对 [Codex request_user_input 协议源码](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/request_user_input.rs) 的问题与答案结构。桌面端 XML 包装没有使用该公开类型，按本机消息样本建立独立测试。

检查了提示词解析、Codex JSONL 读取、轮次记录、简略与详细日志、自动标题、状态同步、DONE 和整理入口。清洗按消息长度线性处理；修复按任务记录与来源轮次建立索引，不扫描或改写整库手写内容，不增加模型调用。

经验：控制消息可能通过用户消息通道传输；读取和落笔都应提取可读内容。保留用户标题时也要跳过空格与前缀规范化。

本机安装后再次扫描，今天日记中的 3 条内部回传标签记录已清除；长标题、双空格和页面链接保留。
