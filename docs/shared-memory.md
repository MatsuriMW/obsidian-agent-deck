# 共享 Dream 长期记忆

## 配置共享文件

在 Agent Deck 设置中打开 Dreaming，找到“与其他 Agent 共享记忆”。

1. 填写共享文件的绝对路径，例如 `/Users/me/shared-agent-memory/memory.md`。也支持 `~/`。使用专用文件，下次同步会覆盖该文件。
2. 点击“立即同步共享记忆”，确认成功状态和时间。手动同步无需开启自动同步。
3. 开启“自动同步共享记忆”，设置同步间隔。每次 Dream 完成后也会同步。

共享文件保留人工说明、当前有效记忆和来源。已拒绝和已被替代的条目会被排除。请在原长期记忆笔记中修改内容，再同步共享文件。

定期同步独立于“每天自动整理”。间隔为 1～168 小时，失败后至少间隔 1 小时重试。Obsidian 和插件必须保持运行；关闭后不会导出，下次运行后继续检查。

## 同步到 GitHub

先将目标仓库克隆到本机，配置 `origin`、当前分支、Git 提交身份和登录。共享文件的父目录必须已存在于仓库内。

将共享文件路径设为仓库中的专用 Markdown 文件，开启“同步后提交并推送 Git”。插件只提交这个共享文件，并推送到 `origin` 的同名当前分支；其他暂存修改保持原样。文件内容没变化时不新增提交，但仍会重试推送。

确认仓库的可见范围适合保存这些记忆。推送失败会保留本地共享文件和错误状态；修复登录、网络或分支问题后，可再次点击“立即同步共享记忆”。插件不会自动合并远端冲突。

## 让其他 Agent 读取

本机 Agent 可以读取同一个共享文件。跨设备的 Agent 先拉取仓库，再读取文件。可以在对应 Agent 的启动说明或项目 `AGENTS.md` 中加入以下说明，并替换为真实路径：

```text
开始任务前读取 /Users/me/shared-agent-memory/memory.md，作为用户偏好和项目经验参考。
用户本次明确表达优先，待验证规律不要当作事实。
如需修改记忆，请更新原 Obsidian 长期记忆笔记，再同步共享文件。
```

这是单向共享。其他 Agent 对共享文件的直接修改会在下次同步时被覆盖。来源链接指向原 Obsidian 库，其他设备若要核对原文，还需访问对应笔记。

## 查看 Dream 进度

点击“现在 Dream 一次”后，按钮会禁用重复点击。界面显示采集、模型整理、写入和同步阶段，以及已经耗用的时间。等待模型时显示持续运行的进度条；完成和失败结果保留在设置页，重新打开页面后仍可看到上次运行时间和错误。

Telegram Companion 的联动设置仅在已安装该插件时显示。已安装但未启用时仍显示设置；实际档案同步需要 Companion 启用且档案已创建。
