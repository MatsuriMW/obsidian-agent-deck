# Agent Deck 1.9.5 修复与验证

日期：2026-11-15。

## 问题与要求

用户指出后台日记回传必须保留结论、改了什么和没做完的事，不能只取回复前一截。

1.9.4 的实际实现是清理格式后截取约 240 字的本地摘录，并未调用 AI 总结。结论或未完成项出现在长回复末尾时会被遗漏。

用户确认：总结失败时保留原文链接并重试，不回退为开头摘录；改完发布 1.9.5。

## 修改

- 完整原文先保存。沿用记录设置中的整理／润色模型，阅读完整回复，输出“结论、改动、未完成”三个非空字段。
- 提示词要求核对末尾，不把计划当完成，不推断已发布或已验证；缺少信息时写“原文未说明”。改动只写具体交付，未发布、未验证和待用户确认事项单独保留。
- 约 240 字只作为目标篇幅；生成后不硬截断。移除后台的原文截取入口和二次字数截断。
- 模型调用在笔记写入队列外执行。总结返回后基于最新笔记合并，保留等待期间的用户输入。
- 总结失败时，笔记显示“总结暂未生成”并保留原文链接，不提交已完成轮次标记。至少等待 60 秒，之后随扫描重试；原笔记不必保持打开。
- 同一轮完整回复的并发请求共享调用，成功结果按内容指纹缓存。后续会话扫描使用同一总结流程，重试使用对应轮次原文。
- 已保存历史与用户手改内容不批量改写。只在未手改且无子项时移除自动生成的待总结提示。

## 尝试与根因修正

原有“原文另存＋本地摘录”保住了原文，但没有完成语义总结。改用三字段 JSON，并验证字段齐全；解析失败和模型离线都进入待总结状态。

检查发现原有任务恢复只在启动时调用，不能保证关闭日志后的总结重试。因此补上常规扫描的待总结重试，并用失败后恢复的回归验证。

## 验证

- 全量 `npm test`、构建、英文覆盖与 `git diff --check` 通过。
- 新增测试覆盖长回复末尾的结论和未完成项、缺失字段／无效 JSON、生成后不再截断、失败后保留原文与重试、并发请求去重、等待期间手写保留，以及后续轮次重试不误用首轮原文。
- 独立真实模型验证：使用现有配置 Codex / gpt-6-luna，在重复排查过程后追加本地修复结论、两项改动及 Windows 未验证／未发布／旧数据迁移待确认。实际返回保留三类信息及全部未完成事项。
- 实际 Obsidian 使用相同真实模型完成一次后台总结回传：三项总结、所有未完成事项、完整原文及回链均保留；等待期间的新手写文字仍在。临时笔记与任务记录已清理。
- 原文读取不取开头或结尾窗口；相同回复复用成功缓存，失败请求至少间隔 60 秒。未新增常驻计时器，沿用扫描周期。

## 依据与边界

沿用已有 `runJournalModel` 及 Claude / Codex 无持久会话、无工具的整理调用。写回继续遵守 [Obsidian Vault 官方原子更新建议](https://docs.obsidian.md/Plugins/Vault)，模型等待不占用文件队列，结果落笔前重读最新内容。

总结质量仍依赖所选模型；字段验证能够发现格式和缺项，不能证明每一句总结都正确。完整原文始终独立保留，方便核对。

经验：短摘录不能替代语义总结。需要保留结论和未完成状态时，应显式要求模型阅读完整材料，并避免在总结之后再次硬截断。
